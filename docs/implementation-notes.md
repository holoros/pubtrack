# Implementation notes: pubtrack 0.2

Build of 10 to 11 October 2026, from pubtrack 0.1 (single author, local SQLite, local Shiny dashboard) found in `~/Documents/Claude/tools/pubtrack`.

## Content inventory against 0.1

**Kept.** Every 0.1 collector (scholarly and SerpAPI Scholar routes, OpenAlex), the matching rules (DOI, exact title, fuzzy title with margin), overrides (merge, exclude, include, set year, set DOI, set OpenAlex), data checks (h mismatch, Scholar to OpenAlex ratio, citation drops, unmatched), every index (h, g, i10, e, hc, hI norm, hI annual, annual h, AWCR, AW, AWCRpA, m quotient, velocity, interim rate, FWCI median and mean, top 10% and top 1% shares), the CSV paper export, the annual summary export, the Publish or Perish import, the systemd timer, and every dashboard view (overview, trajectory with year end reconstruction, papers with history, h core, field impact, data quality).

**Changed.** Single author became multi author (`authors.yml`, `author_id` on runs, works and overrides; schema v2). Storage moved from a local SQLite file to committed CSVs under `data/`, loaded into an in memory SQLite per run. `config.toml` became `authors.yml` plus environment secrets. The Shiny app moved from `r/` to `app/`, reads a prebuilt bundle, and runs in the browser through Shinylive. The field impact view became the portfolio map (FWCI tiers plus projected citations). The systemd timer now runs `scripts/local_scholar_push.sh`. Requires Python 3.9 or later (was 3.11).

**Added.** Comparison across authors (percentile heatmap, career age curves with Hirsch m references, concentration curves and Gini, output per year, authorship roles, shared works). Per paper and per author forecasts with 80% and 95% intervals and an annual backtest gate. Author and publication reports (in app, printable; static HTML per author). Copy ready impact statements. Publish or Perish metrics missing from 0.1 (hm, acc1 to acc20, citations and papers per author, authors per paper). SerpAPI monthly budget planner and cadence per author. OpenAlex title search fallback for works missing from the author's OpenAlex record. Weekly GitHub Actions refresh, test, build and deploy. MIT license.

**Removed.** `smoke-png/` (generated 0.1 outputs; the smoke test now writes to a temporary folder and CI uploads the figures as an artifact). `scripts/make_demo_db.py` (replaced by `make_demo_store.py`, three synthetic authors). The 0.1 demo database survives as `app/tests/fixtures/demo_v1.sqlite`, used to test `pubtrack import-v1`.

## Deviations

- R checks ran locally from the Ubuntu R build and in CI, not on firebreather (SSH refused on 10 October) or Cardinal (connector dropping). Cardinal did run the first Shinylive export successfully.
- `bsicons` is optional at run time because the local R build lacks it; CI installs it.

## Discovered unknowns

- OpenAlex attributes about 30% of the Scholar record to other author ids or omits it. The title search fallback closes part of this; the rest is listed under Data.
- OpenAlex keeps duplicate records for one work (preprint and article). Matching now treats near identical OpenAlex titles as one work.
- OpenAlex title search returns HTTP 500 on parentheses and ellipses. Queries are reduced to plain words.
- The `github-pages` environment was created while `dev` was the default branch and allowed only `dev`; `main` was added.

## Failed repairs

- First forecast (independent per paper Poisson log linear fits, bounded slope): projected 1,514 new citations in 12 months against 1,077 received in 2025. Rejected on the magnitude check. Replaced by empirical Bayes slope shrinkage plus a damped trend; the backtest then predicted 780 (80% interval 733 to 833) against 739 observed for 2025.
- Wrapping every `plot_` function at source time to wrap captions failed under Shiny's autoload environment; replaced by explicit `wrap_caption()` calls at static render sites.

## Deferred

- Semantic Scholar influential citations and intents, OpenCitations cross check, self citation tiers, Ioannidis c-score, Unpaywall OA share, VOSviewer export (see README roadmap).
- Reconstructing Scholar unit year end h before tracking began (the h outlook shows OpenAlex reconstructions in grey).

# Implementation notes: pubtrack 0.2.1 (26 October 2026)

**Why.** The weekly runs of 19 and 26 October refreshed Scholar but failed OpenAlex with HTTP 401: OpenAlex now requires an API key for cursor paging past the first page. The failure sat in `runs.csv` and the job summary while the job stayed green, so every OpenAlex index was stale from 11 October.

**Changed.** `openalex.fetch_works` pages by cursor only when `OPENALEX_API_KEY` is set and by page number otherwise (200 per page, free up to 10,000 results); verified against the live API from firebreather on 26 October (cursor without key: 401 past page 1; `page=2`: 200). `pubtrack sync` gained `--failed-flag`, writes a `::error` annotation per failed source under GitHub Actions, and `--strict` now covers Scholar as well. The workflow fails the sync job after the data commit when the flag file exists and still builds and deploys from the committed data.

**Added.** Annualized indices in the collector (`metrics.compute`, both sources) and in the bundle (`annualized_block` in `app/R/10_data.R`, computed from the bundle so every author has them at once): papers, g and i10 per career year; mean and median citations per paper per year since publication; last five complete years window: citations received, citations per year, h5 and i10 (OpenAlex from counts by year; Scholar from the reported h5 and i10 and the complete year histogram); recent output: papers published in the window, citations to them, their h, citations per recent paper. Exposed in the trajectory metric list, the comparison heatmap (eight new rows), and the key indices table in the app report and the static report. Tests: `tests/test_openalex_paging.py` (three cases) and annualized checks in `test_metrics.py` and `test_pipeline.py`.

**Removed.** Nothing.

**Known limits.** Stored annualized metrics begin with the first sync after this change (OpenAlex from run 7 on 26 October, Scholar from 2 November 2026); the bundle values exist immediately. Scholar h5 and i10 (5 y) are as reported (window includes the partial current year); OpenAlex h5 uses five complete years, so the two are not strictly comparable across sources, only across authors within a source.

# Implementation notes: pubtrack 0.2.2 (26 October 2026, red team round 1)

Two fresh context reviewers attacked 0.2.1 (one the Python collector, one the R bundle, app and reports) with the live store as evidence. Thirty five findings, five majors on each side confirmed against the data; repairs below. Nothing was removed.

**Collector.** Works linked by title search sit on other OpenAlex author ids, so the author filter never returned them again and five of ten had a snapshot in one run only (OpenAlex n_papers 358 to 352 between runs 3 and 4 on the same day). `sync` now refetches title search links missing from the author filter (`fetch_by_ids`, 50 per call), flags a link that no longer resolves as a research work (`stale_link`), and flags any work the author filter returned last run and not this run (`left_record`) instead of keeping it, so OpenAlex reattributions stay visible. Per author indices (hI norm, hI annual, hm, AWCRpA, citations and papers per author, authors per paper) imputed one author where the count was unknown, which for Scholar meant every unmatched entry (90 of 354 dated papers in run 6; papers per author 158 against 91 at the median count): they now use papers with a known count only and `author_count_coverage` is stored beside them. Scholar's reported h5 and i10 (5 y) cover six calendar years (since year is the current year minus 5) and were stored under the five complete year names; they are now `h5_reported`, `i10_5y_reported`, `cites_since_reported`. A merged duplicate whose target has no snapshot in a source kept its citations out of that source; it now stands in for the target. `work_year_counts` rows are deleted before re-insert so a year OpenAlex drops does not survive, and window counts are restricted to works with a snapshot in the run. Page paging now sorts (`publication_date:desc`), refuses a response without `meta.count`, refuses a record over 10,000 works before paging, de-duplicates, and raises on a short read. Truncated authorship lists (OpenAlex caps at 100) leave the author count and last author flag unknown instead of recording 100. `g` pads with uncited papers as Publish or Perish does ([100] gives 10). `min_year` is stored and a configured `first_year` later than the earliest paper is flagged. Empty results (no works, no metrics) are flagged rather than passing as ok.

**Bundle, app, reports.** Projected values are gated at the source: `compare` carries `proj_*` only when the backtest passed, so the heatmap row, the compare table, both key indices tables and the statements honour the gate the Methods card described (previously only the value box and statements did); the per paper frontier, risers and report tables gate through `fmt_interval`; the portfolio point sizes remain ungated and say so; `bt_ran` distinguishes an unavailable check from a failed one. The career h curve joined OpenAlex year end h to the Scholar current h (40 to 50 in one year for this record); it now ends on the current OpenAlex h. The five year window and recent work rows are OpenAlex for every author whatever the unit, heatmap columns carry the unit (GS or OA), rows that are OpenAlex for everyone say so, and the caption warns when a selection mixes units. Statements, the navbar and the report header date Scholar counts by the Scholar run and OpenAlex by the OpenAlex run instead of the newer of the two. The static report's h trajectory now uses the table's unit. Scholar's cumulative citation curves are offset by the citations the profile histogram predates (166 for this record), so career curves start at the right height. `key_indices_table()` and `fmt_interval()` are shared by the app and the static report; NA prints as n/a everywhere, projected h is rounded, `top_papers` drops papers without the ranking key. `[[` replaces `$` on metric lists (no partial matching), `metric_labels` lookups guard a missing name, `recon` is NULL rather than a zero column tibble when no author has an OpenAlex run, heatmap columns are keyed on author id and unit so two authors with one name do not collide, the redundant papers per year (5 y) row is gone, Methods text matches the code (2012 onward, simulation count from the bundle, backtest in OpenAlex units, author count coverage, g padding).

**Deferred (recorded, not fixed).** Metric inputs other than citations (year, author count, exclusion, merge) are mutable columns, so an old run's stored per author indices cannot be reproduced exactly after matching improves (run 1 hI norm stored 24, recomputed 22); a per run paper table would fix it and is a schema change. OpenAlex age metrics run on the Scholar year for linked works. `first_year` can shift by one when the two runs straddle a year end. `--author` with an unknown id exits 0 with nothing due.

**Round 2 (repair attacker on the round 1 diff).** Four majors confirmed and fixed: the by-id refetch had covered every linked work, which would have made the record sticky against OpenAlex reattribution (now title search links only, plus the `left_record` flag); the stand-in duplicate was absent from window counts and FWCI (now the same rule in `window_citations_openalex`, `interim_rate` and the impact query, tested); `g` padded in Python but not in R (now both); the in-app frontier and risers tables were still ungated. Minors fixed: cursor branch also requires `meta.count`; heatmap columns disambiguate two authors with one name; `first_year` flagged once per run; last full year and report dates taken from the unit run; "ten year window" captions corrected to 2012 onward; the per author sums are labelled as known author count papers. Three Cardinal runs (R 4.5.2) of the smoke test, a live bundle build and the static report render passed; the live bundle's window block reproduces the collector's run 7 values exactly (3,441 citations, h5 29, 73 recent papers).
